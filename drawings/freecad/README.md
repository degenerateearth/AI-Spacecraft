# Degen-1 CAD-001 — FreeCAD accommodation model

MODELED / PRELIMINARY / NOT FOR FABRICATION OR FLIGHT.

This translates the existing Revision A spacecraft into editable component
envelopes. It does not substitute a generic 1U design. Read
[TRACEABILITY.md](TRACEABILITY.md) and [FINDINGS.md](FINDINGS.md) before using it.

- `parameters.json`: canonical dimensional inputs, object names, evidence, sources and requirements.
- `build.py`: canonical generator, intersection audit, assigned BOM masses and verification routine.
- `Build_Degen1.FCMacro`: run in the installed FreeCAD GUI to regenerate and preview.
- `exports/Degen1_CAD001.FCStd`: editable native document with Spreadsheet-driven Part boxes.
- `exports/Degen1_CAD001_envelopes.step`: interoperability solids; references and unknown interfaces excluded. All solids are bounding/allocation volumes, not material.
- `exports/assembly.png`: FreeCAD view, when generated by GUI macro.
- `exports/geometry_report.json`: computed overlaps, distances, bounds and mass reconciliation.
- `exports/verification.json`: saved-file and STEP software verification.

## Reproduction

Installed tool: FreeCAD 1.1.3, revision 20260725, Python 3.11 (bundled).
No paid tools, cloud compute or external engineering service used for this CAD work.

In FreeCAD, open the macro through Macro > Macros and Execute. It resolves paths
relative to itself. It creates a new document, retaining any other open document.
Close unsaved variants deliberately yourself; do not confuse them with the saved baseline.

For repeatable command-line generation using this computer's installed FreeCAD:

```powershell
& "$env:LOCALAPPDATA\Programs\FreeCAD 1.1\bin\python.exe" "D:\Degen-1\drawings\freecad\build.py"
& "$env:LOCALAPPDATA\Programs\FreeCAD 1.1\bin\python.exe" "D:\Degen-1\drawings\freecad\build.py" --verify
```

The commands use the actual installed FreeCAD modeling kernel. The GUI macro
also saves colors, transparency and a view. Headless regeneration preserves
geometry but does not produce the same graphical presentation.

Edit the native `Parameters` spreadsheet's B column and recompute to change
dimensions/centers. All boxes have expression-driven size and location.
For durable reproducibility, propagate accepted edits back to `parameters.json`
and regenerate; generation overwrites the saved output files. STEP cannot retain
the expression graph, evidence metadata or unknown-interface records.

`References` contains hidden nominal envelope, bay and service-clearance volumes.
Toggle their visibility for inspection; they are not physical parts or masses.
`UnresolvedInterfaces` contains records without geometry so missing hardware is
visible in the tree. Turn off `SolarPanels` for an internal view.

Geometry checks enumerate every component pair, calculate Boolean intersection
volumes, report distances <=3 mm, and check containment in the project nominal
100 x 100 x 113.5 mm envelope. 3 mm is a reporting threshold, not a requirement.
No universal clearance acceptance, tolerance analysis, mounting validation,
structural simulation, thermal simulation or hardware test is implied.

Verify regenerations by comparing geometry signatures, not FCStd/STEP binary
hashes: files may contain time-dependent metadata. Verification reopens FCStd in
a fresh process, changes camera length through its spreadsheet expression,
restores it, checks all solids and reads STEP back. Expected overlaps are retained.
